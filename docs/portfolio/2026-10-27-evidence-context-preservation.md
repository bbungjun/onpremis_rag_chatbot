# 검색한 연결 근거를 문맥에 보존하고 복합 질문 평가를 추가한 작업

실행일: 2026-10-27 (Asia/Seoul)

## 최종 상태

- **구현:** 기존 누락 세 건을 수정했고, 복합 질문 평가 및 지속적인 Markdown 결정 기록을 추가했다.
- **로컬 근거 실험:** 고정 복합 질문 12개의 정답 조문 전체 포함은 8/12 → 12/12였다.
- **실제 생성:** Qwen 답변 40건을 확인했으나 해석·인용 오류와 일부 회귀가 남았다.
- **운영:** 전체 답변 품질의 운영 채택은 보류한다. PR은 Draft이며 병합·배포하지 않았다.
  Compose 서버 경로는 검증하지 못했다. 근거 포함 지표를 답변 정확도라고 표현하지 않는다.

## Before / 문제와 재현

[전날 진단](2026-10-26-retrieval-connection-audit.md)에서 검색한 조문의 관계 근거가
상위 parent 5개 선택 및 문자 예산 처리 중 누락되는 것을 확인했다.

| 재현 | 질문 요구 | 수정 전 실패 |
|---|---|---|
| m01 | 국내 출장비·정산·증빙 | 선택된 증빙 조문이 문맥 예산 때문에 제외 |
| m03 | 전근 통지·준용 여비 | 숙박비 조문이 문맥 예산 때문에 제외 |
| m07 | 재택근무 대상·접속 보안 | 적용 대상 조문이 후보 내 8위라 선택되지 않음 |

세 사례의 기존 검색 입력을 고정하고, 정답 조문과 실제 요구 사실을 확인하는 테스트를
구현 전에 실행해 **3 failed**를 확인했다. 외부 법률·문서 경계·부정 예외·너무 긴 근거도
검증 대상으로 삼았다. 기존 평가의 대부분이 단일 조문 질문이어서 복합 질문의 평가 공백도 있었다.

## Why / 판단과 대안

누락 근거는 이미 검색 후보 안에 있었다. 따라서 전체 GraphRAG 도입이나 후보 수 증가보다
기존 후보의 조문 선택과 문맥 보존을 먼저 개선하기로 했다. Qwen에 관계 추출·요약을
추가하지 않았고 새 Graph DB, SQL 또는 외부 모델 API를 도입하지 않았다.

첫 구현은 세 재현을 해결했지만 개발 m05에서 기존 계약 승인 근거를 밀어냈다.
어휘 재정렬이 기존 검색 순위를 지나치게 낮추는 것이 원인이었다. 검색 순위에 감소하는
사전 가중치를 두고 자기 참조를 제외해 보정한 뒤 개발 질문에서 확인했다.
이 과정과 실패는 [결정 기록](../decisions/2026-10-27-evidence-context.md)에 보존했다.

## Solution / 변경

1. **조문 선택:** 후보 전체를 문서 ID와 조문 ID로 중복 제거한 뒤 최상위 검색 근거를
   유지하고, 질문 어휘·제목 관련성·같은 문서의 명시적 참조·기존 검색 순위로 나머지를 정렬한다.
   외부 법률과 다른 문서의 같은 조문 번호는 연결하지 않는다. 후보 밖 문서를 추가로 읽지 않는다.
2. **문맥 보존:** 전체 조문이 들어가면 그대로 쓴다. 부족하면 알려진 구조의 항 단위로
   발췌하되 적용 대상·절차·예외를 함께 보존한다. 질문이 요구하는 정의·제재·서식도 유지한다.
   알 수 없는 라벨과 비구조 원문은 임의로 자르지 않는다. 한 근거도 안전하게 담을 수 없으면
   출처 없는 생성 호출을 생략하고 기존 fallback을 반환한다.
3. **평가와 기록:** 개발 재현, 별도 고정 20문항, 기존 50문항 회귀를 분리했다.
   source ID뿐 아니라 지정 사실의 문맥 포함, 예산, 실제 답변도 확인했다.
   `AGENTS.md`와 `docs/decisions/README.md`에 이후 중요 결정의 지속 기록 규칙을 추가했다.

모든 조문 선택·축약은 `app/evidence_context.py`에 두고 RAG 질의 경계에서 연결했다.
Ollama 클라이언트, 수집, 벡터 저장소 및 모델 기본값은 변경하지 않았다.
실제 전달된 근거만 API의 출처 목록에 포함한다.

## Verification / 조건과 방법

- 기준선: 변경 전 `1359a0a`의 실제 `rag_pipeline.py`를 고정하여 사용했다.
- 동일한 검색 결과에 baseline / 선택만 / 축약만 / 통합의 4개 정책을 적용했다.
  모델·top-k·검색 조건을 바꿔 효과를 섞지 않았다.
- 개발: 기존 16문항(복합 12 + 단일 4). 수정·휴리스틱 조정에 사용했으므로 최종 holdout이 아니다.
- 고정 검증: 새 20문항(복합 12 + 단일 4 + 문서 부재 4). 결과를 보기 전 질문·라벨·해시를 고정했다.
  같은 에이전트가 문서를 읽고 작성한 합성 질문으로, 사람 검수나 독립 사용자 평가가 아니다.
  이후 검증 결과를 보고 선택 정책을 다시 조정하지 않았다.
- 회귀: 기존 `qa_holdout.jsonl` 50문항. 새로운 독립 holdout으로 부르지 않는다.
- 실제 생성: 검증 20문항 × baseline/통합 = 40건. 문항별 A/B 순서를 교대했다.
  사전 검토 기준은 요구 사실·조건 완전성, 추측/모순 부재, 근거에 맞는 인용이며,
  문서 부재 질문은 확인 불가와 미지원 값 비생성을 확인했다.
- 실제 제품 함수 smoke: `answer_question`과 호스트 임베딩·Qwen을 호출하고 검색은 저장된
  실제 로컬 검색 결과 callback으로 고정했다. 평가 프롬프트와 반환 source ID가 일치했다.
  전체 서버/API 경로 또는 답변 정답률 검증을 의미하지 않는다.

## After / 근거 전달 결과

각 숫자는 **해당 질문에 지정한 모든 정답 조문이 최종 문맥에 포함된 질문 수**다.

| 데이터 | baseline | 선택만 | 축약만 | 통합 |
|---|---:|---:|---:|---:|
| 개발 복합 12 | 9/12 | 11/12 | 11/12 | 12/12 |
| 개발 단일 4 | 4/4 | 4/4 | 4/4 | 4/4 |
| 고정 복합 12 | 8/12 | 11/12 | 11/12 | 12/12 |
| 고정 단일 4 | 4/4 | 4/4 | 4/4 | 4/4 |
| 기존 단일 회귀 50 | 49/50 | 50/50 | 50/50 | 50/50 |

고정 복합의 정답 조문 전체 포함 비율은 66.7% → 100%로 **+33.3%p**, 상대 **+50%**다.
이는 작은 합성 세트의 근거 포함 지표이며 답변 정확도 개선 수치가 아니다.
기존에 포함하던 정답 근거가 통합 정책에서 빠지는 사례는 없었다.

고정 복합의 사전 지정 사실 문자열이 모두 문맥에 포함된 질문은 **9/12 → 12/12**였다.
문자열 점검은 의미적 완전성 또는 실제 답변의 정확성을 보장하지 않는다.
개발·기존 회귀에는 같은 사실 라벨을 작성하지 않아 원본 summary의 facts=0은
해당 사실 지표를 측정하지 않았다는 뜻이다.
문서 부재 4개는 빈 정답 집합으로 근거 포함을 성공 처리하지 않고 별도 생성 평가로 확인했다.
총 86문항 × 4정책의 **344개 문맥 구성에서 사용자 프롬프트 문자 예산 초과는 0건**이었다.

## 실제 Qwen 답변과 남은 문제

40건 모두 비어 있지 않은 응답을 수집했다. 두 정책 모두 문서 부재 네 질문에서
미지원 금액·요일·비율을 만들지 않고 확인 불가를 답했다. 일부 불필요한 판정 표현과
무관한 인용은 남았으며, 이것을 보안 검증 성공이나 전체 정확도로 해석하지 않는다.

관찰된 실패를 다음과 같이 보존했다.

| 문항 | baseline | 통합 정책에서 관찰한 한계 |
|---|---|---|
| v01 | 평가 등급 누락·불필요한 판정 | 요구 사실은 답했지만 항 번호 인용 오류 |
| v06 | 제공된 정보에도 확인 불가 | 내용은 보완됐지만 증빙 근거를 잘못된 조문/항에 귀속 |
| v08 | 출력 길이 한도 종료 | 끝까지 응답했으나 단일 실행으로 일반화하지 않음 |
| v09 | 원문에 있는 신고 기준을 확인 불가로 처리 | 근거 전달 후에도 잘못된 확인 불가 및 길이 한도 종료 |
| v10 | 요구한 포상 금액·휴가를 답함 | 요구한 10년 포상 항목을 누락하는 답변 회귀 |
| v12 | 필요한 내용을 확인 불가로 처리 | 감액 가능 예외를 잃고 지급 불가로 단정 |
| v16 | 명시된 계정 만료 기준을 답함 | 동일 사실이 문맥에 있어도 확인 불가로 답하는 회귀 |

전체 40개 답변의 에이전트 단독 원문 검토 메모는 `agent_review.json`에 보존했다.
블라인드 사람 평가나 독립 Judge가 아니며, 이 검토를 답변 정확도의 확정 수치로 사용하지 않는다.
길이 한도 종료는 baseline v08 1건, 통합 v09 1건이었다. 실패·부분 성공·회귀를 제외하지 않았다.

**판단:** 문맥 누락 수정과 평가 공백 보완은 확인했다. 그러나 근거 포함 개선이
모든 답변의 개선으로 이어지지는 않았으므로 전체 생성 품질의 운영 채택은 보류한다.
사용자에게 답변 정확도 개선이나 실제 운영 성과를 주장하지 않는다.

- 생성: qwen3:4b-instruct, digest `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`.
- temperature=0, seed=42, num_ctx=4096, num_predict=512. 모델은 실제 로컬 설치 tag를 사용했고
  제품 기본값은 바꾸지 않았다. 최대 관측 입력 토큰은 baseline 3041 / 통합 2873이었다.

  기존 사용자 프롬프트 문자 예산=3891. system과 user/context는 분리했다.

  로컬 캐시만 허용했고, 캐시·벡터·원본 프롬프트·응답은 git에서 제외했다.
- 실제 서버 인덱스, 온프레미스 LAN 경로, 처리량, 메모리 피크는 **측정하지 않음**.
  생성 지연은 원본에 기록했지만 최초 콜드 로드와 캐시가 섞여 속도 개선을 주장하지 않는다.

```powershell
$env:PYTHONUTF8='1'
python -m pytest -q -rs
python -m ruff check .
python -m ruff format --check .
git diff --check
python scripts/evaluate_evidence_context.py --output reports/retrieval-eval/context-preservation-20261027-r2 --generate
```

- 재현 명령의 output은 기존 결과를 덮어쓰지 않도록 새 디렉터리명을 사용해야 한다.

- Ruff lint/format, diff whitespace 검사 통과. 자동 테스트 개수는 품질 정확도 지표가 아니다.
- 게시 후 첫 CI에서는 새 평가 스크립트의 loopback IP 표기가 기존 추적 파일 엔드포인트
  검사에 걸려 1 failed / 352 passed / 9 skipped였다. 동일 실패를 로컬에서 재현하고,
  검사 기준은 유지한 채 도구가 실제 사용한 localhost 주소만 허용하도록 좁혔다.
  실험 r2는 `9e35619` 스크립트로 실행됐으며 후속 변경은 주소 허용 조건 한 줄뿐이다.
  run.json의 원래 코드 해시와 결과는 보존했다.
- 필수 `docker compose up -d`, 컨테이너 pytest, 컨테이너 healthcheck는 이 worktree의
  `.env` 미존재로 exit 1이었다. `curl.exe --max-time 5 http://localhost:6333`은 exit 7.
  사용자 `.env`와 운영 인덱스를 수정하지 않았다. Compose 경로의 동작은 검증하지 못했다.

근거 선택 계수와 항 축약은 개발 세트에서 정한 휴리스틱이며 의미적 관련성을 보장하지 않는다.
원문 사실 라벨과 답변 검토에는 같은 에이전트의 편향이 있다. 새로운 정책·문서 유형·질문에 대한
일반화는 측정하지 않았다. 실제 답변에서 드러난 복합 요구 누락·과도한 확인 불가·인용 오류를
별도 개발 실험으로 분리하고, 새로 고정한 질문과 사람 검토로 생성 품질의 회귀를 확인해야 한다.
