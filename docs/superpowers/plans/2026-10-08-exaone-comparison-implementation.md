# EXAONE 비교 실행 계획

1. 기존 작업 트리와 기본 모델, 설치 모델, 하드웨어 상태를 기록한다.
2. prompt capture와 요청 동일성, 오류 집계, 불완전 실행 거부의 테스트를 먼저 작성한다.
3. 50개 일반 및 40개 공격 질문의 실제 검색 문맥을 저장하고 corpus/prompt/source hash를 고정한다.
4. 임베딩 모델을 내린 뒤 Qwen, EXAONE 순서로 한 번씩 워밍업 후 순차 생성한다.
5. 일반 50문항의 각 A/B를 무작위로 섞어 모델명을 가린다. 모델명 매핑을 열기 전에
   정답 대비 핵심 내용 일치를 2(핵심 조건 충족), 1(부분 답변 또는 조건 누락),
   0(핵심 오류 또는 정답 누락)으로 기록한다. 차이의 근거를 함께 남긴다.
   정답과의 불일치가 검색 문맥 때문인지 애매하면 frozen prompt를 확인한다.
   이는 단일 Codex 판독이며 사람 평가나 독립 검증으로 부르지 않는다.
6. 오류/지연/출처 및 보안 규칙 점수를 계산하고 판독 결과를 확정한 후 모델명을 복원한다.
7. 실측 결과와 제한, 실패 사례, 재현 명령을 포트폴리오 문서에 기록한다.
8. 이번에 추가한 파일만 별도 origin/main 기반 worktree에서 검토/검증/커밋하고 PR을 만든다.
   실제 실험은 현재 작업 트리에서 했으므로 해당 revision과 미커밋 코드 hash를 명시한다.
