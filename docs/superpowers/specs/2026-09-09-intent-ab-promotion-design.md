# A/B 재검토와 기본값 승격 기준

## 문제와 범위

EXAONE 점수는 답변 누락과 모순을 놓쳤다. 사용자는 현재 대화 세션에서 재검토하고 A/B 비교에
따른 승격을 요청했다. A는 canonical 질문에 원문을 사용하는 후보, B는 현재 예측 intent 지시문이다.
승격 후보의 변경 범위는 canonical 지시문에 한정한다. 정규화, 기존 검색 재작성, system prompt,
출처/무답 처리는 동일하다. 해석기 전체 삭제나 검색 재작성 삭제로 결과를 일반화하지 않는다.

## 재검토 기준

후보 문자열의 사실, 문맥 근거, 요청한 정보의 완전성, 출처를 직접 대조한다. 정보가 없는 것과
불허/미충족은 구분한다. 무답이 적절한 문맥이면 정답 참조에만 있는 내용을 요구하지 않는다.
누락을 근거 오류와 혼동하지 않는다. 둘 다 실패하면 both_fail로 기록해 승리를 강제하지 않는다.

- critical: 근거 없는 허용/불허/미충족 판정, 핵심 기준에 대한 반대 결론, 허구의 근거 조항.
- required_fact_missing: 주 질문에 필요한 사실 누락(실패이나 별도로 표시).
- pass: 제공된 문맥에 맞는 핵심 정보를 모순 없이 제공하고 출처를 표시.
- A/B 입력이 같으면 차이를 intent 효과로 집계하지 않는다.

대화 세션의 AI 검토이며 이전 결과와 arm을 알고 있다. 독립 사람 평가나 블라인드 평가가 아니다.
실제 backend model ID는 확인되지 않았으므로 current-session AI review로 표기한다.

## 표본과 전향적 보완

점수가 갈린 9건(q11/q26/q29/q32/q43/q45/r14/r46/r48)을 진단 표본으로 검토한다.
동점 대조 q01(명확한 기한), q41(교육 횟수와 시간)을 함께 검토한다. 선택 편향 때문에 이
11건의 합격률이나 승률을 전체 RAG 품질 개선으로 보고하지 않는다.

새 보완 표본은 내일/2일 뒤/3영업일 뒤/4일 뒤(주말 미상) 연차 4문항이다. 기존 98건에는
lead_time 추출 및 검색 재작성 발동 사례가 0건이었다. 문항과 기대 조건을 생성 전에 고정하고,
기존 B의 검색 질문으로 한 번 검색해 A/B에 동일 문맥을 제공한다. 3개의 서로 다른 seed로
반복한다(4문항 x 2조건 x 3회 = 24답변). 기존 canonical builder를 사용하며 생성 결과를 보고
질문, 판정 기준, 프롬프트를 바꾸지 않는다. Qwen은 답변 생성에만 사용한다.

## 승격 게이트

A를 기본값으로 바꾸려면 다음을 모두 만족해야 한다.

1. 새 critical regression 없음: 같은 문항/반복에서 B는 critical 오류가 없고 A에만 있는 사례 0.
   진단 표본에서도 발견된 명백한 오류를 무시하지 않는다.
2. 실제 입력이 달라진 반복 표본에서 A가 B보다 나빠진 결과가 없고 적어도 한 문항에서 개선.
   같은 입력에서 발생한 승리는 효과 근거로 쓰지 않는다.
3. 대표성 있는 독립 확인 세트와 검증된 채점 기준의 근거가 확보돼야 최종 기본값 승격 가능.
   이번 진단/4문항 stress set은 그 자체로 통계적 동등성/우월성을 증명하지 않는다.

어느 조건이 미달이면 hold로 기록하고 기존 기본값 B를 유지한다. 승격 판정 파일은 코드나
설정을 자동 변경하지 않는다. 실패하면 원인을 해결한 별도 후보를 새 실험으로 검증해야 한다.

## 구현/검증

기존 평가 산출물은 보존한다. 새 보완 질문 JSONL, 평가 전용 prepare/generate CLI, session
review JSON과 승격 게이트를 추가한다. 원문/답변/평가 세부는 ignored reports/local-judge에 둔다.
사전 문서/판정 기준, 게이트 테스트, 동일 문맥/seed/checkpoint 테스트를 먼저 작성한다.
Docker 전체 테스트와 서비스 확인 후 포트폴리오 문서와 기존 PR을 업데이트한다.
