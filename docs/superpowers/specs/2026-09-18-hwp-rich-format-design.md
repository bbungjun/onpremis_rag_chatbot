# HWP 서식 내용 보존 파싱 설계 (2026-09-18)

## Before / 문제

현재 `read_document`는 HWP CLI의 Markdown 문자열을 조·항 정규식으로 청킹한다. 합성 HWP에서 표와 번호 목록은 문자열에 남지만, 표의 열-값 관계는 청크에 명시되지 않는다. 각주 정의는 문서 끝에 출력되어 참조한 제3조가 아닌 뒤의 제4조에 붙었다. 이미지는 `![image]()`만 출력되어 내부 글자는 색인되지 않았다. 이 상태에서는 출력에 parent/child가 존재해도 답변 근거가 다른 조에 귀속될 수 있다.

## 선택한 인터페이스

외부 호출자는 계속 `read_document(path) -> str`만 사용한다. 내부에서는 HWP CLI의 Markdown 추출을 기본 텍스트 순서로 사용하고, 서식별 보강을 한 모듈에 모은다.

```text
HWP 5.0
→ hwp cat --format markdown
→ 이미지가 있으면 hwp convert --media-dir로 로컬 자산 추출
→ 표·번호 목록·각주·이미지 텍스트 보강
→ 기존 편/장/절/조/항 정규화와 청킹
→ child 임베딩·Qdrant
```

표는 헤더와 각 행의 열-값 관계를 읽기 좋은 문장으로 만들고 병합 셀은 병합 범위를 표시한다. 번호 목록의 항목 순서는 보존한다. 각주 정의는 참조 표지가 있는 문단으로 옮긴다. 이미지는 추출한 자산에 로컬 OCR을 적용한다. OCR 엔진이 없으면 실패하고, OCR 결과가 비었어도 캡션·설명이 있으면 보존한다. 세 항목이 모두 비면 색인을 중단한다.

## 범위와 한계

- 표, 자동 번호 목록, 각주, 이미지 텍스트를 동등한 검증 대상으로 둔다. 하나의 합성 HWP에서 모두 재현하고 병합 표는 별도 fixture로 확인한다.
- 사용자가 지정한 이미지 범위는 내부 글자 OCR과 캡션이다. 글자가 없는 그림·도식의 의미 해석은 이번 단계에서 다루지 않는다.
- HWP CLI JSON IR에는 표 셀, 각주 제어 개체, 이미지 참조가 있지만 현재 MVP의 청킹 인터페이스를 전면 교체할 만큼의 실제 서식 샘플이 없다. Markdown 보강은 검증 가능한 중간 단계이며 HWP 원본의 모든 레이아웃·서식을 재현한다고 주장하지 않는다.
- 생성 문서는 실제 회사 규정이 아니다. OCR 품질과 실제 사내 HWP 커버리지는 독립 샘플에서 평가한다.
