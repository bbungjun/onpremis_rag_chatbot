# 사용하지 않는 AWS 생성 경로 제거 설계 (2026-09-18)

## Before / 문제

사용하지 않는 AWS 관리형 생성 경로가 서버 route, 모델 adapter, Streamlit 세 번째 패널, 발표용 비교 화면, 환경 변수, AWS SDK 의존성, 테스트 및 문서에 남아 있다. 모델 ID와 자격 증명 설정을 요구하고, 운영자가 사용하지 않을 기능의 상태와 실패를 보게 만든다.

## 범위와 선택

- AWS 관리형 생성 클라이언트, RAG wrapper, 서버 endpoint/health 항목, 요청 필드, UI 패널과 설정, 관련 테스트와 의존성을 제거한다.
- 현재 사용하는 로컬 Qwen 경로와 별도 Gemini 비교 경로를 유지한다. 발표용 비교 화면의 API 패널은 이미 존재하는 Gemini RAG 경로에 연결한다.
- 발표용 저장 예시는 질문과 필터만 남긴다. 이전 공급자의 저장 답변을 Gemini 응답으로 재표기하지 않는다.
- AWS 배포 일반 설정은 생성 경로와 별개로 검토한다. 이 공급자 전용 `.aws` 마운트는 제거한다.
- 현재 코드와 문서에서 제거 대상 명칭, 모델 ID, 환경 변수와 SDK 의존성이 남지 않도록 한다. 역사적 구현 계획 중 전용 문서는 폐기하고 혼합 문서는 현 상태에 맞춰 정리한다.

## 검증

- 제거 후 서버 route와 응답 스키마가 로컬/Gemini만 노출하는지 테스트한다.
- 두 UI가 로컬/Gemini만 요청하고 상태를 표시하는지 테스트한다.
- 전체 pytest, Ruff, 정적 검색을 실행한다. Docker가 가용하면 AGENTS.md의 필수 검증 명령을 실행한다.
- 검색/답변 품질 개선은 이 작업의 측정 대상이 아니다. 포트폴리오 기록에는 제거 전 실패 재현과 제거 후 검증, 환경 한계를 적는다.
