# 합성 사내규정집 DOCX·PDF 두 버전 생성 설계 (2026-09-19)

## Before / 문제

기존 대규모 합성 규정은 정책 1,000개를 HWP 한 권으로만 생성했다. DOCX와 PDF 수집 경로가 추가됐지만 그 규모의 동일한 원문 두 버전은 없어서 형식별 추출·청킹 회귀를 비교할 수 없다. 다른 문구를 따로 작성하면 파일 형식의 영향과 내용 차이를 분리할 수 없다.

## Why / 선택

`make_regulation_book(1000)`을 단일 논리 원문으로 사용한다. 이전 HWP의 생성 Markdown과 줄바꿈 정규화 후 내용이 같음을 확인했다. 이전 파일은 Windows CRLF로 2,263,783바이트(SHA-256 `12ef5904d881632e0d27fcaf959302c54437448ed9af014ee814d7c72853552b`)였고, 논리 텍스트의 LF UTF-8은 2,197,364바이트(SHA-256 `0e7ff46082dc68eb10790e9b619c48d207e95fc381a977543d7977698ebc6510`)다. 내용 비교는 정규화된 텍스트와 조·항·답 문구로 한다.

DOCX는 편집용 규정집으로 제목 스타일과 문단을 쓰고, PDF는 동일 원문을 페이지에 배치한 배포용 텍스트 PDF로 만든다. 두 파일을 같은 폴더에 색인하면 중복이므로 생성 산출물은 비교 대상으로만 사용하며 색인할 때 한 형식을 선택한다.

## Solution / 계약

- 재현 가능한 생성 스크립트가 `--count`와 `--output`을 받아 DOCX 한 파일과 PDF 한 파일을 쓴다. 기본 목표는 1,000개 정책이다.
- 두 파일에 같은 편/장/절/조/항 문구를 같은 순서로 배치한다. 합성 문서임을 제목·메타데이터에 표시한다.
- 생성 직후 두 파일을 기존 `read_document`로 다시 읽어 조 8,000개, 항 24,000개, 청크 ID 고유성과 개발 질문 1,000개의 대상 조·답 문구를 확인한다.
- DOCX/PDF를 프로젝트의 무시된 `output/`에 보관하고 파일 해시·바이트·페이지 수·실행 조건을 manifest와 포트폴리오 문서에 기록한다. 생성물을 Git에 포함하지 않는다.

## 검증과 한계

작은 2정책 생성·재추출 테스트를 먼저 작성한다. 1,000정책 실행 후 DOCX의 구조 검증, PDF 텍스트 추출과 페이지 렌더, 내용 매핑을 확인한다. 전체 페이지를 렌더·검토할 수 없는 경우 정확한 범위와 차단 원인을 기록한다. 합성 템플릿의 반복 문구는 실제 회사의 다양한 서식·개정·권한·스캔 PDF를 대표하지 않는다. Qdrant 적재·검색과 Qwen 답변은 이 문서 생성 작업의 측정 범위 밖이다.
