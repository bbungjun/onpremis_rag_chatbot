# Qwen과 EXAONE의 고정 문맥 비교

## 문제와 범위

현재 설정 `qwen3:4b-instruct`와 설치된 `exaone3.5:7.8b`를 동일 PC에서 비교한다.
기본 모델을 변경하지 않는 로컬 실험이다. 기존 50문항 일반 합성 세트와 40문항
무답/공격 합성 세트를 재사용한다. 이전에 사용한 세트이므로 새로운 비공개 홀드아웃이 아니다.

## 결정

- 현재 작업 트리의 RAG 검색/질문 해석/parent 확장을 한 번 실행해 system/user
  메시지, 출처, 검색 시간을 저장한다. 모델별로 재검색하지 않는다.
- 일반 질문은 `llmenhance_chunks`, 공격 질문은 `llmenhance_adversarial`을 읽는다.
  저장된 payload의 parent 내용이 현재 평가 문서와 같은지 먼저 확인한다.
- 설정은 top-k 5, context 4096, output 최대 2048, temperature 0.2,
  seed 42, repeat_penalty 1.0을 양쪽에 적용한다. 반복 페널티와 seed는 이번 실험의
  명시적인 통제 조건이다. 기본 런타임의 생략된 모델별 기본값과 구분한다.
- 두 모델은 Q4_K_M이지만 4B/7.8B로 크기가 다르다. 계열 자체의 우열로 일반화하지 않는다.
- 임베딩을 끝낸 뒤 임베딩 모델을 내리고 생성 모델을 하나씩 적재한다.
  각 모델의 짧은 워밍업은 측정에서 제외한다. 모델별 순차 단일 실행이며 순서 효과가 남는다.
- 오류, 빈 출력, 토큰 상한 종료, 원문, prompt hash, Ollama 시간/토큰/적재 정보를 모두 남긴다.
  생성 시간은 검색 시간과 별도 보고하며 합성 합계를 실제 E2E 측정으로 표현하지 않는다.
- 보안 평가는 기존 문자열 기반 거절/canary/출처 검사 규칙을 변경 없이 사용한다.
  정성 품질은 모델명을 숨긴 답변과 정답/문맥을 Codex가 판독한다. 사람 평가가 아니며
  규칙 검사나 단일 AI 판독을 실제 사용자 정확도로 표현하지 않는다.
- 기존 EXAONE Judge는 자기 모델 평가 편향이 있어 이번 우열 판정에는 사용하지 않는다.

## 완료 기준

두 모델의 모든 원본과 오류를 로컬 reports에 보존하고 동일 prompt hash를 확인한다.
일반 답변/보안/속도/자원 결과와 실패 사례, 검증 장애를 포트폴리오 문서에 기록한다.
기존 미커밋 변경은 이번 실험에 포함해 커밋하지 않는다.
