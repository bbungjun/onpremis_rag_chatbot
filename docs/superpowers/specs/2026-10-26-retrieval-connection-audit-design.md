# 기존 검색의 조문 연결 누락 진단

작성일: 2026-10-26 (Asia/Seoul)

## Before / 확인할 문제

GraphRAG 도입 전에 현재 검색이 실제로 조문 사이의 연결을 놓치는지 확인한다.
기존 development 50문항 중 복수 정답 조항은 1건이고, holdout 50문항은 모두
단일 정답 조항이다. 이 평가만으로 복합 질문의 근거 충족을 판단할 수 없다.

## Why / 구분할 원인

1. 규정 원문에 필요한 사실 자체가 없는 경우
2. 필요한 조문이 검색 child 후보에 없는 경우
3. 후보에는 있으나 parent 상위 5개에 포함되지 않는 경우
4. parent에는 있으나 기존 문맥 예산 처리에서 제외되는 경우
5. 근거가 전달되어도 생성 모델이 답하지 못하는 경우

서로 다른 시점의 검색 결과와 생성 결과를 연결해 원인을 확정하지 않는다.
과거 산출물은 후속 점검 대상을 찾는 데만 사용한다.

## 진단 방법과 사전 고정

- 현재 합성 규정집의 본문에서 명시적인 조문 참조를 추출한다.
- 제목의 자기 참조와 외부 법률의 조문 참조를 내부 연결로 세지 않는다.
- 검색 실행 전에 별도 진단 질문 12개와 단일 조문 대조 질문 4개를 고정한다.
- 정답 조문은 질문의 각 요구 사항을 근거로 지정한다. 참조된 모든 조문을
  무조건 정답으로 지정하지 않는다.
- 이 데이터는 문서를 읽고 만든 목적 표집 development 진단 세트이며,
  기존 holdout의 대체나 새로운 독립 holdout이 아니다.
- top_k=5, child 후보=20, 현재 질문 해석과 dense+BM25 RRF 및 문맥 조립을 사용한다.
- 실행 환경의 설정, 소스/질문/데이터 해시 및 모델 식별자를 저장한다.
- 현재 서버에 접근할 수 없다면 host Ollama bge-m3와 Qdrant Local 메모리
  컬렉션에 현재 문서를 새로 적재해 진단한다. 기존 인덱스는 변경하지 않는다.
- 서버 결과와 메모리 재구축 결과는 구분한다. 현재 서비스 성능으로 표현하지 않는다.
- Qwen 답변 및 Judge는 호출하지 않는다. 근거 전달까지만 측정한다.

## 측정과 판정

- 각 단계에서 필요한 모든 정답 조문이 존재하는 질문 수를 분모와 함께 기록한다.
- 단계별 누락 조문 ID와 검색 순위, 남은 명시적 연결을 기록한다.
- 명시적 연결의 존재는 원문을 읽고 검토한다. 그래프 확장의 효과는 측정하지 않는다.
- GraphRAG가 필요하다는 결론은 검색 누락과 문맥 잘림을 구분한 뒤 제안한다.
- 원문이나 민감한 로컬 결과를 추적 문서에 복사하지 않는다.

## 범위

제품 검색, 프롬프트, 모델, 인덱스 및 사용자 작업 파일은 변경하지 않는다.
재현 가능한 진단 스크립트·진단 데이터·검증 테스트와 최종 증거 문서를 추가한다.
원본 실행 결과는 git에서 제외된 `reports/retrieval-eval/` 아래 보존한다.
