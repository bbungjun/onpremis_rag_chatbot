# 검색 근거의 선택 및 보존 설계

문제와 선택 기록: [의사결정 기록](../../decisions/2026-10-27-evidence-context.md).

## 문제

고정 상위 parent 선택은 복합 질문의 보조 조문을 밀어내고, 전체 조문을
예산 뒤에서 제거하는 방식은 이미 선택한 필수 근거까지 잃는다.
단일 정답 조문 위주의 기존 평가만으로는 이 실패를 검출하기 어렵다.

## 인터페이스와 책임

`app/evidence_context.py`는 문서 구분이 있는 후보 조문과 원 질문,
최대 출처 수, 문자 예산 및 기존 프롬프트 렌더 함수를 받아 선택된 근거와
최종 프롬프트를 반환한다. 이 모듈은 네트워크·LLM·벡터 저장소에 접근하지 않는다.

`rag_pipeline._build_context`는 필터가 적용된 기존 검색 후보 전체를 조문으로
중복 제거한 후 이 정책에 전달한다. 최종 출처는 실제 선택·전달된 근거만 포함한다.
`_expand_to_parents`의 기존 정렬/중복 제거 API는 유지한다.

## 선택·축약 정책

- 최상위 검색 결과를 보존하고 나머지는 질문 관련성과 같은 문서 참조로 정렬한다.
- 외부 법률 참조와 다른 문서의 동일 번호 조문을 근거 확장에 사용하지 않는다.
- 전체 원문이 들어가면 그대로 보낸다.
- 예산 부족 시 적용 대상·절차·예외 항 전체를 보존한 발췌를 사용한다.
  질문이 묻는 다른 종류의 항도 보존한다. 명확한 항 구조가 없으면 임의 절단하지 않는다.
- 최종 프롬프트 렌더 길이를 검사하고 실제로 담을 수 있는 근거만 반환한다.
  한 개의 근거도 들어가지 않으면 기존 문서 부재 fallback으로 생성 호출을 생략한다.
- 모델이나 top-k 증가로 효과를 섞지 않는다. 새 SQL/Graph DB/외부 API는 추가하지 않는다.

## 검증

먼저 실패 재현, 문서 경계, 외부 법률, 예외·부정 보존, 긴 단일 근거,
너무 긴 사용자 질문과 실제 생성 호출의 출처 일치 테스트를 작성한다.
개발 세트와 별도 고정 세트에서 동일 검색 결과의 구성 정책만 비교한다.
실제 답변과 원문 사실 보존은 출처 ID 포함과 별도로 평가한다.
